# 定位与导航诊断：2026-11-02

## 测试条件

- 使用当前安装包、默认 world/map/config，无界面启动；独立 ROS_DOMAIN_ID=69、Gazebo master 端口 11359。
- Gazebo 出生位置为 (-5.15, 5.15, yaw=0)，显式发送同位置初始位姿，初始 x/y/yaw 方差均为 0.01。
- 导航目标 (-4.45, 4.90, yaw=0)，距名义出生位置约 0.74 m。
- 测试读取同一时刻附近的 `/odom` 与最新 TF，不是用户原先运行的 rosbag；本次结果只能证明该配置可复现异常。

当前生成地图的坐标按 Gazebo world 对齐，且 Gazebo 插件默认使用 world 真值里程计；因此上述增长不能解释成轮速里程计积分漂移。一般系统中 map 和 odom 原点可以不同，不能普遍以两组坐标之差作为定位误差。

导航结果为 `STATUS_ABORTED` (6)。规划器报告机器人起点超出全局代价地图范围，`worldToMap` 的索引为 (25, 221)，地图大小 (220, 220)。此时 map 中估计 y 已超过地图上界 5.5 m，而仿真里程计 y 约为 4.90 m。

日志还报告 inflation_radius=0.10 小于含 footprint padding 的内切半径 0.265 m。当前目标容差为位置 0.20 m、角度 0.20 rad，无证据需要继续放宽容差。

原始测量见 `probe.log`，控制器和导航器日志见同目录。测试进程已停止。本次仅纠正里程计来源的说明，未修改用户的 AMCL、MPPI 或代价地图参数。

## 处理顺序

1. 使用当前 `/scan` 与 `/odom` 重新建图，另存文件，不覆盖原几何投影图。AMCL 使用扫描对应的定位地图；二维激光看不到的低矮边界应通过规划禁行区等方式限制通行。
2. 用新地图重启 AMCL，并在 RViz 提供初始位置与朝向。新建地图原点可能不同，不能直接假定初始 map 坐标等于 Gazebo 出生坐标。
3. 分别检查 `map -> odom` 和 `odom -> base_footprint`。前者由 AMCL 或 SLAM 二选一发布，后者由唯一里程计发布；不要用静态 TF 固定 map 与 odom 来掩盖定位误差。
4. 地图与扫描对齐后，将两张代价地图的膨胀半径调整至至少覆盖机器人内切半径，并同步 MPPI ObstaclesCritic 的膨胀配置；确保起点和目标具有足够障碍物间距，再测试短距离导航。
